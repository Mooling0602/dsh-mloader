# dsh-mloader 包格式

[English](Package.md) | 简体中文

本文规定承载可安装 dsh-mloader 插件的归档，以及所有包共用的安装、更新和删除规则。它适用于 Python 包和 WebAssembly 包。各后端自己的布局见 [python-sdk/Package](python-sdk/Package.zh.md) 和 [wasm/Package](wasm/Package.zh.md)。

状态：Python 后端通过 [python-sdk/Package](python-sdk/Package.zh.md) 第 6 节规定的运行时命令行实现了本文。WebAssembly 后端仍是目标契约。加载器本身从不从归档安装插件：安装会写出加载器随后发现的解压后目录。

包是一个 zip 归档。它在归档根放一份插件清单，以及清单指定的文件。加载器会先解压归档再加载内容，所以归档只是传输格式，永远不是插件运行的目录。清单决定后端、入口点和平台目标，因此归档布局与清单不能互相矛盾。

## 1. 归档文件名

包的文件名只是给人看的约定。加载器从不解析它，从不校验它，也从不从它推导插件身份、版本或平台。任何合法的文件名都可以，不遵循命名约定的包与遵循约定的包安装方式完全相同。

约定的后缀是 `.mloader.pack` 和 `.zip`。加载器按内容识别包，不按后缀识别，所以后缀不同、甚至没有后缀的文件，只要字节是 zip 归档，仍然是一个包。

WebAssembly 包永远不是可执行程序。它不能以 shebang 行开头，根目录下不能有 `__main__.py`，加载器会拒绝这样的归档。Python 包可以是 `.pyz`（[python-sdk/Package](python-sdk/Package.zh.md) 第 2 节），但加载器仍然只解压它，从不执行它。

文件名里出现的平台、编译器或版本信息只是参考。插件 id、版本、后端和平台目标的唯一权威是清单。

## 2. 归档根

- 归档根只放一份 `mloader.plugin.json`。根之下的清单不描述第二个插件：加载器不会解压它所在的目录，并报告一条警告。
- 加载器在解压任何内容之前先校验清单。根下没有清单、或清单违反 schema 的包会被拒绝，不会创建插件目录。
- 后端布局规则叠加在本节之上。它们分别见 [python-sdk/Package](python-sdk/Package.zh.md) 和 [wasm/Package](wasm/Package.zh.md)。

## 3. 解压安全

包是不可信输入，所以加载器在写入任何字节之前校验每个归档条目：

- 带绝对路径的条目会被拒绝。
- 通过 `..` 逃出插件目录的条目会被拒绝。
- 符号链接条目会被拒绝。
- 超过条目数上限或解压后大小上限的归档会被拒绝。当前上限是 4096 个条目和 512 MiB 解压后内容。

被拒绝的包不会留下不完整的插件目录。

## 4. 安装、更新与删除

包的内容要先解压，加载器才能加载它们。加载器从不导入归档里的代码，所以一个存在但未安装的归档不会贡献任何插件。对 Python 包，[python-sdk/Package](python-sdk/Package.zh.md) 第 6 节的命令行负责解压、更新检查和索引写入。加载器仍然只读取已安装的目录。

对于名为 `web` 的 profile，清单设置 `"id": "test"` 的包会解压到这个目录：

```plaintext
~/.dsh/profiles/web/mloader/plugins/test
```

目录名来自清单里的插件 id。归档文件名从不参与，因为插件 id 来自清单，目录名只是跟随它的约定。

归档文件留在用户放置它的位置。加载器读取它，但从不修改或移动它。

### 4.1 安装索引

加载器把 `.mloader.index.json` 写入解压后的插件目录。它记录这次安装的内容：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersion` | 整数 | 本索引格式的版本。当前版本是 `1`。 |
| `id` | 字符串 | 插件 id，等于清单的 `id`。 |
| `installedAt` | 字符串 | 首次安装的 ISO 8601 时间戳。 |
| `updatedAt` | 字符串 | 最近一次安装或更新的 ISO 8601 时间戳。 |
| `packageFile` | 字符串 | 安装插件所用归档的文件名。 |
| `packageMd5` | 字符串 | 归档文件的小写十六进制 MD5。 |
| `fileMd5` | 对象 | 从插件目录相对路径到该文件小写十六进制 MD5 的映射。 |

`fileMd5` 覆盖归档提供的文件。索引从不列出自己，因为它在解压完成后才写入。

打包者可以在归档里附带一份 `.mloader.index.json`，提前发布逐文件校验和。这样的索引可以设置 `schemaVersion`、`id` 和 `fileMd5`，不能设置 `installedAt`、`updatedAt`、`packageFile` 或 `packageMd5`，因为这些字段描述的是打包者并未执行的安装。归档带有这样的索引时，安装器在解压前按其中的 `fileMd5` 校验归档条目，并为安装后的文件写一份新索引。安装索引覆盖最终目录，对 Python 插件来说，这个目录可能包含合并后的 `pyproject.toml`，且不再有 `requirements.txt`，所以安装器拥有的字段总是压过归档里的值。

### 4.2 更新

在已有插件上安装更新的包，就是更新插件的方式。在解压任何内容之前，加载器把新归档的 MD5 与已安装索引里的 `packageMd5` 比较。

| 情况 | 行为 |
| --- | --- |
| MD5 不同 | 已安装的插件目录移到回收站，新包解压到原位置。 |
| MD5 相同 | 归档与已安装的归档字节完全相同。加载器在重新安装前请求二次确认。 |

比较的是归档文件的字节，所以内容相同但重新打包的归档，只要 zip 元数据不同，MD5 就不同，重新构建正是这种情况。因此重新打包的归档会被当作新版本，即使插件源码没有变化。Python 命令行把这次二次确认表达为 `--force`。

环境提供平台回收站时，回收站就是平台的回收站目录；环境不提供时，已安装目录会移到 `$TMPDIR` 下，该位置在重启后不保留。更新会替换上一次安装，所以回收站只是恢复窗口，不是回滚点。

已安装索引带有 `fileMd5` 时，加载器先核对磁盘上的文件。不再匹配的文件是在安装后被编辑过，意味着用户拥有这项改动。加载器随后列出被改动的文件，发出警告，并在替换目录前请求二次确认。

### 4.3 删除

删除插件的方式是删掉它在 `mloader/plugins` 下的目录，或把它移到回收站。加载器提供同样的操作，并先请求二次确认。Python 命令行把这次确认表达为 `--yes`。删除插件从不触碰安装它所用的归档，所以同一个归档可以再次安装它。

## 5. 版本兼容性

`schemaVersion` 给索引格式定版本，不给插件定版本，也不给 ABI 定版本。加载器读到 `schemaVersion` 高于自己已知版本的索引时，会拒绝更新那个插件，并报告它读到的版本，因此旧加载器永远不会覆盖新加载器做过的安装。

清单 schema 单独定版本。清单违反该 schema 的包会在安装时被拒绝，且在解压任何内容之前。

## 6. 格式的限制

- **没有签名，也没有发布者身份。** `packageMd5` 只能发现归档变过。它不认证是谁构建的，加载器也没有信任库。只从你信任的来源安装包。
- **共享格式没有依赖契约。** 归档只携带打包者放进去的文件。Python 包在 [python-sdk/Package](python-sdk/Package.zh.md) 第 4 节补上了依赖契约，由运行时把声明的依赖安装进共享的 profile 环境。WebAssembly 包不能声明依赖。
- **没有安装钩子。** 安装从不执行插件代码，所以包不能运行安装步骤、导入模块或调用函数。
- **没有回滚。** 更新把上一个目录移到回收站。回收站是恢复窗口，不是回滚点。
- **没有部分安装。** 被拒绝的包不会留下插件目录。
- **一个归档一个插件。** 归档根之下的第二份清单不是插件，也不会被当作插件解压。

## 7. 打包者检查清单

- 清单位于归档根。
- 归档只携带一个插件，并满足 [python-sdk/Package](python-sdk/Package.zh.md) 或 [wasm/Package](wasm/Package.zh.md) 的后端布局规则。Python 包可以携带 `pyproject.toml` 和 `requirements.txt`；合并规则见 Python 包布局。
- 发布归档只构建一次，分发这个文件。重新打包相同内容会改变 MD5，因为 zip 元数据变了，加载器会把它当作新版本。
- 打包者可以在归档里附带带 `fileMd5` 的 `.mloader.index.json`，提前发布逐文件校验和。第 4.1 节说明随包索引可以设置哪些字段。
